# TokenVault Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build two Windows installers: a Manager desktop app (NitroSense-style dashboard + employee-installer generator) and a per-user Adapter agent that streams Claude Code token usage to the Manager over the company LAN.

**Architecture:** One repo, one `tokenvault` package with `common` (pure, no I/O), `adapter`, `manager`, `ui`. Adapter tails `~/.claude/projects/**/*.jsonl` by offset, queues events in a SQLite outbox, and sends them over a pinned-certificate WebSocket to the Manager, which upserts into SQLite, maintains rollups, and pushes live updates into a pywebview HTML/ECharts UI.

**Tech Stack:** Python 3.11+, playwright (dev, UI tests), pywebview (WebView2), websockets, cryptography, watchdog, pystray + Pillow, SQLite (WAL), ECharts (SVG), pytest, ruff, mypy, PyInstaller, Inno Setup.

**Spec:** `docs/superpowers/specs/2026-11-19-tokenvault-design.md` (read it first; section numbers below refer to it).

## Global Constraints

- Python 3.11+; Windows 10 21H2+/11; WebView2 runtime bundled via bootstrapper in the Manager installer.
- Free only: no cloud, no paid certificate/signing. Installers are unsigned (SmartScreen documented).
- Ingest: WebSocket over TLS (>= TLS 1.2), default port **47800**, Manager is the server; self-signed cert generated by the Manager, SHA-256 fingerprint pinned by the adapter; no openssl, no CA.
- Event row keyed by **`message_id`** (fallback `uuid`); upsert on `(device_id, message_id)`; if usage differs keep the larger value. Never key on `uuid` alone (overcounts ~2.3x).
- Wire fields per event: uuid, session_id, message_id, timestamp, model, reasoning_effort, is_sidechain, input_tokens, output_tokens, cache_read_tokens, cache_create_5m_tokens, cache_create_1h_tokens, project (last folder of `cwd` only), session_title, tool_names (names only), claude_account_email, account_uuid, windows_user, hostname, team, device_id.
- Never sent: prompt/reply text, tool inputs/outputs, file contents, full paths.
- Adapter budget: ~0% CPU idle, <1% average while Claude is active, <40 MB RAM, no polling loop (file-change notification + offset tail, debounce <= 1 s), below-normal priority, network only to the Manager. Delivery target 1-2 s.
- Adapter installs per user, no admin (`%LOCALAPPDATA%`, HKCU Run), one outbox per Windows user, `device_id` = machine + Windows user. No pause button; tray icon + "What is sent?" view always present.
- Manager runs from the tray; closing the window hides it; ingest keeps running. Only the Manager installer needs UAC (firewall rule).
- Cost is "API-equivalent estimate", computed at query time from `data/pricing.json`; unpriced model => cost UNKNOWN, never guessed. Only raw tokens are stored.
- Missing `oauthAccount` => "Unknown account (windows_user@host)", never dropped.
- UI: Acer NitroSense style (chamfered frameless window, hatch background, red #e10b1f/#ff2d3f, angled panel tabs, tick-mark gauges), Vietnamese strings in one i18n resource file.
- Chart colours (owner request): diverse, professional, readable on the dark NitroSense background. Red stays the brand/accent (gauges, titles, primary line) but data series use a categorical palette: `#ff4d5e` red, `#ffb020` amber, `#2dd4bf` teal, `#4da3ff` blue, `#a78bfa` violet, `#7ee787` green, `#f472b6` pink, `#94a3b8` slate. A model/project/employee keeps the same colour on every page (stable hash -> palette index, defined once in `ui/js/palette.js`); contrast >= 4.5:1 for labels on panel background; never encode meaning by colour alone (legend + tooltip labels). Follow the `dataviz` skill when writing chart code.
- Code quality: layered, `ruff` clean, `mypy` clean, no file > ~400 lines; `adapter` never imports `manager`; UI talks to Python only through `manager/api.py`.

## Review Focus

1. A transcript's last line is half-written when read -> not consumed; offset stays before it; next run reads it whole. (Task 5)
2. A transcript is truncated/replaced (prefix hash mismatch) -> re-baseline that file without double counting already-delivered `message_id`s. (Task 5)
3. Manager certificate fingerprint mismatch or Manager IP now serves something else -> adapter refuses, sends nothing, keeps queue. (Task 8)
4. Same `message_id` appears on many lines / with differing usage -> exactly one row, larger usage wins; Vietnamese or emoji in session titles and Windows user names round-trip intact. (Tasks 3, 7)
5. Port 47800 already taken on the Manager PC -> Manager picks the next free port, shows it, and installers it generates carry that port. (Tasks 8, 10)

### Task 24: Adapter on macOS (owner request: install on both Mac and Windows)

**Rulings:** (a) Windows stays the primary, tested platform; macOS code is written behind a platform seam and unit-tested with injected fakes on Windows; real-Mac verification is a manual checklist (`docs/e2e-checklist.md`, section "macOS"). (b) PyInstaller cannot cross-compile: the macOS adapter template is built on a Mac with `build/build-mac.sh`. (c) macOS delivery format: Manager's "Create installer" for target macOS outputs a ZIP `TokenVault-Adapter-<team>-mac.zip` holding the unsigned template `TokenVault Adapter.app` + a sidecar payload file `tokenvault-config.bin` (same TVLTCFG1 encoding, CRC) + `Install.command` (double-click; removes quarantine attribute `xattr -dr com.apple.quarantine`, copies the app to `~/Applications`, runs `adapter setup --from <payload>`, registers LaunchAgent). Appending payload to a Mach-O is NOT used (breaks code signature). (d) Secrets on macOS: Keychain via the `security` CLI (no plaintext fallback; fail closed like DPAPI). (e) Autostart: `~/Library/LaunchAgents/vn.ics.tokenvault.adapter.plist` (RunAtLoad, KeepAlive=false-on-clean-exit), loaded with `launchctl bootstrap gui/<uid>`. (f) Tray: pystray works on macOS only on the main thread; if unavailable run headless with a menu-bar fallback disabled and still honour the consent screen (use `osascript` dialogs instead of tkinter). (g) Paths: `~/Library/Application Support/TokenVault`, logs `~/Library/Logs/TokenVault`; Claude data still `~/.claude`. (h) Singleton: `fcntl.flock` lock file. (i) Background priority: `os.nice(10)` + `taskpolicy`-equivalent via `os.setpriority`. (j) Watcher: watchdog uses FSEvents; keep the hot-file stat poll.
